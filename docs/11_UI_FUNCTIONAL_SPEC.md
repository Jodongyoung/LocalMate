# LocalMate 화면·버튼 기능 명세 v1.2

> 이 문서는 UI **배치/시각 디자인을 지정하지 않습니다.** 개발자는 화면별 입력/버튼/동작만 준수하고 디자인은 자유롭게 결정합니다.

작성 2026-10-22. 기준 문서: 01_PRD, 02_SRS, 04_API_CONTRACT. API와 충돌 시 담당자 합의 후 계약을 변경합니다.

- **UI-02** 통합 대시보드 (FR-010/018/021/025/030)
- **UI-03** AI 비서 (FR-016/017/021/026)

## 화면별 필수 컨트롤/동작

### UI-01 로그인 / 사업장 선택
관련 요구사항: FR-001~003

- **이메일·비밀번호 입력 · 로그인**: POST /auth/login; 인증 오류를 표시하고 성공하면 대시보드로 이동
- **사업장 선택 목록 · 사업장 선택**: GET /businesses; 허용된 사업장만 선택하고 전역 사업장 컨텍스트 갱신
- **공통 헤더 · 사업장 변경 / 로그아웃**: 다른 사업장 선택 시 화면 데이터·대화·선택 상태 초기화; 로그아웃은 로컬 인증정보 해제

**상태/제약:** 로그인 실패·인증 만료·선택 사업장 없음·권한 없음 상태 지원

### UI-02 통합 대시보드
관련 요구사항: FR-010/018/021/025/030

- **기간 선택 · 기간 변경 / 새로고침**: 해당 기간의 리뷰 집계·운영 지표·인사이트 API 다시 요청
- **반복 문제 및 인사이트 · 근거 보기**: 원문 리뷰 ID·분자/분모·기준 기간을 표시; 고객 관리로 이동
- **승인 대기 제안 · 제안 상세 보기**: 승인 화면으로 이동; 대시보드 카드에서 자동 실행 금지
- **AI 요약 영역 · AI 비서에서 질문하기**: 현재 사업장 컨텍스트로 AI 비서 화면 이동

**상태/제약:** 업종별 주요 지표가 달라야 하며 합성 데이터 표시 및 데이터 부족·모델 오류 상태 분리

### UI-03 AI 비서
관련 요구사항: FR-016/017/021/026

- **자연어 입력 · 전송**: 대화 메시지 API; 답변에 근거 링크, 로딩, 실패/재시도 안내
- **현재 대화 · 새 대화**: POST /conversations; 사업장별 분리, 기존 대화 변경 없음
- **AI 답변 내 근거 · 출처 확인**: 해당 리뷰·집계 기간으로 이동하여 자료와 연결
- **업무 제안 카드 · 제안 상세 / 승인 검토**: 먼저 제안 전체 내용·대상·도구·버전을 보여주는 화면 열기; 승인 전 업무 변경 없음

**상태/제약:** 자동 도구 실행 금지. 모델이 만든 수치·권한 판단을 프론트에서 승인된 사실로 표시하지 않음

### UI-04 고객 관리(리뷰·문의)
관련 요구사항: FR-005~010/019/026

- **목록 검색 조건 · 기간 / 유형 / 분석 상태 필터**: GET /feedback; PENDING/SUCCEEDED/FAILED/STALE 구별
- **직접 입력 폼 · 리뷰/문의 등록**: POST /feedback; 유효성 검사 후 목록 갱신
- **CSV 업로드 · 파일 선택 / 업로드**: POST /imports/feedback; 수용·거절 행 수와 오류 내용 표시
- **목록의 개별 리뷰 · 분석 요청 / 결과 확인**: POST /feedback/{fid}/analyze; GET /feedback/{fid}/analysis
- **분석 상세 · 근거 원문 보기**: 근거 인용이 원문 어디에 있는지 표시; 성공·실패·오래된 결과 구분
- **응대 초안 · 초안 미리보기 / 저장 제안 검토**: POST /draft-previews; 미리보기만으로 저장하지 않음. 저장은 승인된 업무 제안을 통해 수행

**상태/제약:** 원문·감성·문제 유형·근거와 실패 상태를 구분; 사업장 바깥 자료 절대 노출 금지

### UI-05 매장 운영(업종별)
관련 요구사항: FR-011~015

- **공통 선택 · 기간 변경 / 데이터 갱신**: 선택 사업장 업종에 맞는 집계만 표시
- **카페 화면 · 매출 CSV 업로드**: POST /imports/sales; 메뉴별/시간대별 매출·수량 집계 조회
- **미용실 화면 · 예약 CSV 업로드**: POST /imports/bookings; 시술별/시간대별 예약·상태 집계 조회
- **집계 결과 · 기간 다시 적용 / 오류 확인**: GET /operations/sales-summary 또는 /operations/booking-summary

**상태/제약:** 다른 업종 전용 UI 숨김. 예약 변경·실제 POS 연결·판매/예약 자동 조작 버튼은 제공하지 않음

### UI-06 마케팅 / 응대 초안
관련 요구사항: FR-019/020/021/023

- **초안 생성 설정 · 초안 생성 / 다시 생성**: POST /draft-previews; 사업장 정책·근거를 표시, 외부 게시 기능 없음
- **초안 영역 · 미리보기 내용 확인 / 복사**: 화면 미리보기 상태이며 저장·전송과 구분
- **초안 저장 흐름 · AI 비서에 저장 제안 요청**: AI 비서로 이동해 save_marketing_draft 또는 save_reply_draft 제안 생성 요청; 실제 저장 전 승인
- **저장 초안 목록 · 저장된 초안 보기**: GET /drafts; 승인 후 생성된 결과만 표시

**상태/제약:** 현재 API 계약에는 별도 초안 저장 버튼용 POST가 없음. 새 저장 API를 임의 제작하지 말고 API 변경 합의

### UI-07 업무 관리 / 승인 / 이력
관련 요구사항: FR-021~025/027

- **제안 목록 · 상태 필터 / 상세 보기**: GET /proposals; 승인 대기·거절·완료·실패 구분
- **제안 상세 · 승인 / 거절**: POST /proposals/{pid}/approve 또는 /reject; 대상·본문·도구·해시를 먼저 표시
- **승인 확인 · 최종 확인**: 사용자의 명시적 조작 후 plan_sha256을 그대로 전송; 중복 클릭은 서버 멱등성으로 보호
- **실행 결과 · 결과 확인 / 다시 조회**: GET /executions/{eid}; 상태 SUCCEEDED/FAILED/UNKNOWN별 안내
- **실제 업무·초안 · 업무 목록 / 초안 목록**: GET /tasks, GET /drafts; 실제 생성된 레코드와 실행 근거 제시

**상태/제약:** 가장 중요한 데모 화면. 제안이 변경되면 이전 승인 사용 금지; 승인 전 업무 0건·반려 시 실행 없음

### UI-08 사업장 설정
관련 요구사항: FR-002/003/030

- **사업장 프로필 · 현재 정보 확인**: GET /businesses/{bid}; 업종·지역·사업장 소개 표시
- **운영 정책 · 정책 편집 / 저장**: PATCH /businesses/{bid}/policy; 버전 충돌 시 다시 불러오기
- **사업장 컨텍스트 · 사업장 전환**: 소속된 사업장만 전환; 관련 상태/캐시 초기화
- **데이터 안내 · 데모 데이터 표기 확인**: 합성·실제·Mock·모델 이름을 알 수 있는 표시

**상태/제약:** 업종·지역·소개 편집은 현재 API에 없음. 화면은 읽기 우선, 수정 필요 시 API 계약 변경 합의

## 공통 개발 규칙

- **화면 구성 자율성:** 이 문서는 화면/버튼/동작만 지정한다. 배치·색상·폰트·컴포넌트 스타일·메뉴 구성은 프론트엔드 담당자가 결정한다.
- **공통 UI 필수 상태:** 로딩 / 빈 데이터 / 권한 없음 / 입력 오류 / 분석 실패 / 모델 장애 / 데이터 부족 / 합성·Mock 출처를 구분한다.
- **변경 업무 승인:** AI 제안이나 미리보기만으로 tasks 및 draft_artifacts를 생성하지 않는다. 승인 버튼은 확인 단계 후 서버가 실제 승인 상태를 확인한다.
- **P0 외 버튼 금지:** SNS 게시, 외부 리뷰 답글 게시, 실제 예약 변경, 고객 메시지 발송, 결제, 재고 발주는 MVP에서 제공하지 않는다.
- **API 계약 우선:** 존재하지 않는 서버 엔드포인트를 UI 개발자가 임의 정의하지 않는다. 필요한 경우 먼저 04_API_CONTRACT를 팀 합의로 업데이트한다.
- **순차 구현:** 첫 스프린트는 로그인/사업장 선택 → 리뷰 목록/등록 → 카페 대시보드 → AI 비서 → 제안 승인 → 실행 결과 순으로 연결한다.

## API 계약 갭
- 독립 초안 저장 API 없음: AI 비서를 통한 승인 제안 재사용 또는 계약 변경.
- 수동 업무 상태 수정·사업장 프로필 PATCH API 없음: P0 조회 전용, 변경 필요 시 계약 합의.
- 대화 목록 조회 API 없음: 현재 대화 메시지 조회가 기본; 목록 추가는 계약 합의.
- 외부 플랫폼 자동 게시/예약 수정 API 구현 금지.

## 개발 지시
프론트 담당자는 UI-01~08을 Mock 기반으로 구성한 뒤, BE 준비 상태에 맞춰 실제 API를 연결하세요. 임의로 API 응답 필드와 상태를 invent하지 마세요. 승인 전 변경 0건, 중복 승인 결과 1건, 사업장 간 데이터 격리, 모델 오류 상태가 최소 E2E 검증 조건입니다.
